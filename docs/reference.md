# Mycel: полное описание

Коротко о Mycel и быстрый старт — в [README](../README.md) (по-русски — [README.ru.md](../README.ru.md)). Здесь — всё подробно: интерфейс, команды агента, HTTP API, хранение и разработка.

Свободная карта продукта: блоки с текстом, заметки-стикеры, подкарты внутри блоков и связи между блоками. Всё двигается, растягивается и соединяется мышью. Одно локальное приложение хранит карты всех ваших проектов. AI-агенты (Claude Code, Codex и другие) подключают проект сами, строят его карту, пока вы смотрите, читают карту целиком и узнают о ваших правках — через `mycel.mjs` или HTTP API.

Замысел и требования: [CONCEPT.md](../CONCEPT.md). Состояние реализации и проверки: [PROJECT_STATE.md](../PROJECT_STATE.md).

## Запуск

Нужен **Node.js 22+**. Внешних зависимостей, сборки, облака и ключей AI-провайдеров нет; `npm install` не требуется.

Двойной клик по **`Mycel.cmd`** (Windows) или **`Mycel.command`** (macOS; один раз `chmod +x Mycel.command`) запускает Mycel в фоне и открывает его в браузере: [http://127.0.0.1:4317](http://127.0.0.1:4317). Если Mycel уже работает, просто открывается страница; если работает Mycel старой версии с теми же данными (после обновления программы), он перезапускается. Node.js ищется в PATH, а в Windows ещё и в рантайме Codex. Из терминала то же самое — `node mycel.mjs open`; остановить — `node mycel.mjs stop`.

Все данные приложения лежат рядом с программой, в `.mycel/` (исключён из Git, поэтому `git pull` их не трогает): реестр проектов, их карты, события для агентов (что человек сделал кнопками Mycel) и отметки агентов. В папки проектов Mycel ничего не пишет.

До версии 0.15 программа называлась «Контур»: `kontur.mjs`, `Kontur.cmd`, данные в `.kontur/`, MCP-сервер `kontur`. При первом запуске Mycel переименовывает `.kontur/` в `.mycel/` (если там не работает хаб прежней версии — его сменяет `Mycel.cmd`), прежние переменные `KONTUR_*` читаются, если нет `MYCEL_*`. MCP-сервер нужно подключить заново под именем `mycel` (см. «MCP» ниже).

## Проекты

Главная страница — список проектов: название, папка, число блоков и время последней правки; зелёная точка — агент ждёт сообщений. Новый проект появляется в списке сразу, как только агент его подключил; клик открывает карту. Корзина в строке удаляет проект (только его карту в Mycel, не папку), «Вернуть» в уведомлении отменяет удаление; удалённые проекты хранятся в `.mycel/trash/` 7 дней.

Сверху строка «Агенту: http://127.0.0.1:4317/agent». Клик копирует фразу для агента: «Прочитай инструкцию Mycel и выполни её: curl.exe -s http://127.0.0.1:4317/agent». Вставьте её в окно агента в папке проекта (Claude Code, Codex): агент подключит проект (`mycel init`), а если папка уже подключена — продолжит работу с её картой. Разговариваете вы с агентом в его окне: чата в Mycel нет. Пустую карту агент строит по ходу чтения кода: сначала концепции, затем механику каждой из них с техникой и кодом внутри, — и на холсте видно, как появляются блоки, блоки внутри блоков и связи. Пока вы не двигали карту, вид сам следует за новыми блоками; любое своё движение это выключает, «Показать всё» включает снова.

Внутри проекта «‹ название» в нижней строке возвращает к списку.

## Работа с картой

- **Создание**: правый клик по пустому месту — «Блок» или «Заметка». Сразу можно печатать: Enter переводит из названия в текст, Ctrl/⌘ + Enter, Esc или клик мимо завершают ввод. Пустой блок или заметка исчезают.
- **Подкарты**: правый клик по блоку — «Блок внутри» или «Заметка внутри». Блок становится контейнером и сразу получает просторное поле: сверху его название и текст, ниже холст подкарты. Блоки внутри двигаются свободно; чтобы перенести блок в подкарту, перетащите его на её поле (оно подсвечивается), чтобы вынести — отпустите за пределами поля. Если содержимому тесно, поле растёт и запоминает размер; угол меняет размер, но не меньше содержимого. Шеврон в углу или пункт меню «Свернуть подкарту» превращает её в компактную карточку с числом блоков и заметок внутри, клик по этой надписи разворачивает обратно. Правый клик по полю подкарты создаёт узел прямо там. Связи соединяют блоки любых уровней; вложенность до 8 уровней.
- **Заметки**: правый клик по блоку — «Заметка к блоку». Это стикер, который переезжает вместе с блоком и удаляется вместе с ним. Заметку можно отодвинуть куда угодно: она остаётся прикреплённой, а между ней и блоком видна пунктирная ниточка. Перетащите заметку на другой блок того же уровня, чтобы перекрепить: заметка основной карты, брошенная на подкарту, прикрепляется к самому контейнеру, а не к вложенному блоку. Брошенная на блок заметка встаёт рядом с ним — справа или под ним, где ближе, — а не на его текст. «Открепить от блока» есть в её меню.
- **Правка**: карандаш в правом верхнем углу блока (виден при наведении и у выделенного блока) сразу открывает правку названия и текста, у блока с подкартой — тоже, без погружения. Двойной клик по блоку без подкарты или по заметке — правка названия или текста под указателем. Название и текст блока с подкартой правятся ещё по Enter на выделенном блоке или через «Изменить» в его меню. Перетаскивание двигает, правый нижний угол меняет размер.
- **Отметки** — только рамкой, блок не заливается: без готового кода — пунктир (новый блок, созданный на карте, сразу такой), идёт проверка — рамка пульсирует, проверен — зелёная, проверка не прошла — красная; подкарта, внутри которой что-то проверяется или не прошло, показывается так же. Отметки ставит агент (`mark`) по ходу тестов; каждая смена приходит сразу и вспыхивает кольцом (у блока в свёрнутой подкарте — у её карточки).
- **Предложение агента**: новое — пунктиром с подсветкой, изменённое — подсвечено, к удалению — бледное и зачёркнутое; свёрнутые подкарты с предложенным раскрыты, вид переезжает к нему. Его можно править как обычно; внизу посередине карты — название, «Отклонить» и «Принять». Решение уходит агенту вместе с правками (в `wait` и `changes`) и коротко подтверждается на экране.
- **Погружение**: двойной клик по блоку с подкартой открывает его — на карте только этот блок с развёрнутой подкартой, подкарты вложенных блоков свёрнуты (виден ровно один уровень ниже), сверху путь «Карта › … › Блок», вид плавно переезжает к блоку. Двойной клик по вложенному блоку с подкартой — ещё на уровень глубже. На уровень вверх — Esc (если ничего не выделено и не редактируется) или двойной клик по пустому месту; звено пути переходит сразу туда. Погружение — тот же фокус (агент видит, где человек), одна запись в истории, агентов не будит. «Открыть» в меню любого блока открывает его так же: в блоке без подкарты следующий уровень создаётся через «Блок внутри».
- **Связь**: потяните за любой край блока (при наведении он подсвечивается, курсор — крестик), за кружок на правом краю или с зажатым Alt из любого места блока. Линия со стрелкой тянется за курсором, над блоком встаёт так, как ляжет готовая связь, и блок подсвечивается. Отпустите в любом месте другого блока: связь получает блок под курсором — из лежащих друг на друге верхний, из вложенных самый глубокий; блок, от которого тянете, не мешает, поэтому можно связаться и с блоком, который он закрывает. Бросок на прикреплённую заметку связывает с её блоком, у самого края блока — с ним; отпускание в пустом месте ничего не создаёт. Tab на выделенном блоке создаёт связанный блок справа. Связи соединяют только блоки.
- **Выделение**: клик по блоку показывает панель с цветом, кнопками «Связать» и «Удалить»; правый клик открывает меню действий с блоком. Delete удаляет выделенное; удаление блока вместе с его содержимым и заметками, удаление заметки и удаление связи можно отменить из уведомления.
- **Связи**: при наведении линия подсвечивается, в её середине появляется крестик удаления, а на концах — ручки, которые можно сразу перетащить на другой блок; у подписанной связи крестик стоит над подписью. Наведение на блок подсвечивает все его связи. Клик по связи выделяет её: появляются подпись, смена направления и удаление. В меню связи есть «Перенести начало на…» и «Перенести конец на…» для переноса кликом. Удаление связи можно отменить из уведомления. Связь не может замыкаться на себя и повторять существующую.
- **Раскладка экрана**: карта на всю ширину и под ней строка управления, как в n8n: вкладки «Карта» и «История», ползунок уровня, точка агента и скачивание карты. Над строкой — что агент делает сейчас, когда он об этом сообщает. Если под картой мало места, строка переносится на несколько линий.
- **Уровни**: ползунок в нижней строке с четырьмя делениями — концепция, механика, техника, код; рядом название выбранного уровня. Щелчок по делению, перетаскивание (карта меняется, когда ползунок отпустили) или стрелки, когда он в фокусе. Если подкарты свёрнуты вразнобой и ни один уровень карте не подходит, бегунок тусклый и без названия; щелчок по любому делению выравнивает карту. Концепцию и механику читает человек, который не программирует: блоки основной карты — концепция (что это за часть и зачем), их подкарты — механика (как она работает, шагами, понятными без программирования); коротко и без кода. Подкарты механики — техника для разработчиков: компоненты, файлы, библиотеки, настройки, данные, технические риски. Подкарты техники — код: шаги в порядке выполнения, функции и файлы в `обратных кавычках` (моноширинным шрифтом). «Концепция» сворачивает все подкарты, «Механика» показывает подкарты основной карты, «Техника» — ещё уровень ниже, «Код» разворачивает всё. Когда подкарта разворачивается, соседи справа и снизу раздвигаются, при сворачивании возвращаются; заметки блока едут вместе с ним всей стопкой. Вид карты зависит только от того, что свёрнуто: уровень, погружение и выход из него возвращают всё на прежние места. Если свёрнутая карточка со своими заметками всё же ложится на что-то (например, стопка справа — на заметку под серединой подкарты), то, на что она легла, сдвигается вправо или вниз и там и остаётся. Подкарта, которая выросла от правки (блок внутри неё перетащили к краю, «Блок внутри»), тоже раздвигает соседей и держит свои заметки рядом.
- **Агент**: чата в Mycel нет — с агентом говорят в его окне (Claude Code, Codex). Точка в строке управления: зелёная — агент ждёт ваших действий, жёлтая — работает; имя — в подсказке. Над строкой — что он делает сейчас («читаю server.mjs», со шкалой, если известна доля). Когда агент показывает блок, карта переходит к нему (в его подкарту) и выделяет его. Что вы выделили на карте и в каком блоке работаете, агент видит — «сделай вот это» ему понятно.
- **Фокус**: двойной клик по блоку с подкартой или «Открыть» в меню блока (то же погружение) — работа над одним модулем или этапом. На карте остаётся только этот блок со всем вложенным; сверху путь к нему («Карта › … › Модуль», клик по звену переходит туда) и действия «Блок внутри» и «Заметка». Уровни переключаются в пределах модуля, правый клик по пустому месту создаёт узел внутри модуля. Агент видит, на каком блоке человек в фокусе. Esc поднимается на уровень выше (у блока основной карты — выходит из фокуса), ✕ и «Карта» в пути выходят сразу. Модуль вписывается в окно вместе с прикреплёнными заметками.
- **Шкала задания**: пока агент выполняет задание, над нижней строкой появляется полоса со шкалой из сегментов, текущим шагом и процентом; если агент не сообщает процент, по шкале бежит отсвет. Готовое задание несколько секунд показывает полную зелёную шкалу.
- **Холст**: перетаскивание фона двигает карту, колесо прокручивает, Ctrl/⌘ + колесо или щипок меняют масштаб. Кнопки масштаба внизу слева; «Показать всё» вписывает карту в окно.
- **История**: автор, время и причина последних 200 изменений. Кнопка в правом верхнем углу скачивает карту с историей.

Цветовая тема следует системной настройке. Положение и масштаб холста запоминаются в браузере.

## Агенты

Агенту достаточно адреса **`http://127.0.0.1:4317/agent`**: там инструкция с готовой командой Mycel для этого компьютера (полный путь к node и `mycel.mjs`, строки для PowerShell и bash). Без сервера ту же инструкцию печатает `node mycel.mjs guide`. Текст инструкции — [src/agent-guide.md](../src/agent-guide.md).

`mycel.mjs` — командная строка для агентов. Её запускают из папки проекта: проект находится по папке (корень — ближайшая папка с `.git`, подпапка подключённого проекта относится к нему, git worktree — к проекту основного репозитория, а репозиторий внутри подключённой папки получает свой проект), а если Mycel не запущен, команда запускает его сама (вывод — в `.mycel/server.log`). Она помнит, какую ревизию прочитал каждый агент (отметку хранит Mycel), показывает правки других после этого чтения и записывает только поверх прочитанного: если карту успели изменить, вместо записи печатает изменения.

```sh
node mycel.mjs init                    # подключить папку: тот же проект, если уже подключена, иначе новый
node mycel.mjs projects                # все проекты: id · название · папка («папки нет», если её перенесли)
node mycel.mjs init --project ural     # подключить проект ural к этой папке (его папку перенесли или переименовали)
node mycel.mjs init --name 'Урал'      # переименовать проект уже подключённой папки (id и карта прежние)
node mycel.mjs open                    # запустить Mycel, если не работает, и открыть в браузере
node mycel.mjs stop                    # остановить Mycel
node mycel.mjs context                 # вся карта в Markdown: блоки с полным текстом и уровнем, вложенность, заметки, связи с id; что выделил человек и его новые действия в Mycel
node mycel.mjs context --focus server  # только блок со всем вложенным и его связи с остальной картой
node mycel.mjs changes                 # что изменили другие после последнего чтения
node mycel.mjs wait                    # ждёт действия человека в Mycel или чужой правки содержимого, печатает и завершается
node mycel.mjs build map.json          # структура; без x и y блоки расставляются сами; пишется по шагам
node mycel.mjs propose plan.json       # предложение человеку: как build и (или) operations, "title"; решает человек
node mycel.mjs mark promo,summa passed # отметка: plan (пунктир), testing (идёт проверка), passed (зелёная рамка), failed (красная), none
node mycel.mjs apply ops.json          # пакет операций; - вместо файла читает стандартный ввод
node mycel.mjs selection               # что человек выделил на карте и в каком блоке работает, с полным текстом
node mycel.mjs doing 'читаю server.mjs' --progress 40  # что агент делает сейчас: строка под картой; doing --done снимает
node mycel.mjs show summa              # показать человеку блок: карта переходит к нему и выделяет его
node mycel.mjs check summa             # запустить команды проверки (test) блока и вложенного: рамки зеленеют и краснеют по ходу
node mycel.mjs fresh summa             # описание блока верно после правки его файлов: снять «возможно устарел»
node mycel.mjs touch cart/total.ts     # файлы, которые агент меняет (то же делает хук Claude Code): их блоки «правится сейчас»
node mycel.mjs review --hours 24       # что изменилось в устройстве проекта, по концепциям, простыми словами
node mycel.mjs health                  # красные, устаревшие, без проверки, план, TODO и похожее на ключи в файлах блоков
node mycel.mjs overview                # короткий обзор карты (его же хук даёт агенту в начале сессии)
node mycel.mjs plugin                  # собрать плагин Claude Code для этого компьютера
```

Текст для `doing` — в одинарных кавычках: в двойных PowerShell и bash ломают обратные кавычки. Отметка о прочитанном сохраняется до печати, поэтому обрезанный вывод (`| head`, `Select-Object -First`) её не теряет; вывод `wait`, `changes` и `build` агенту лучше читать целиком.

**Удалённый проект.** Если человек удалил проект, команды отвечают «Проект «X» удалён человеком» и не подключают его заново; новый проект на той же папке — только `init --new`, по просьбе человека.

**Код и карта.** У блока могут быть `files` — пути от корня проекта (папка — с `/` в конце) — и `test` — команда проверки (`node …` запускается тем же node, что и Mycel). Когда агент меняет файл (хук Claude Code после правки или `touch`), блоки этого файла на карте подписаны его именем 2 минуты и помечены «устарел?», пока агент не опишет их заново (правка названия, текста, файлов или проверки) или не подтвердит описание (`fresh`); в `context` они перечислены. `check` ставит блокам `testing`, запускает каждую команду один раз из корня проекта и сразу отмечает её блоки `passed` или `failed`. У человека в меню блока с командой проверки — «Проверить»: событие `kind: 'check'` будит агента. `doing --on <id,…>` показывает, над какими блоками работает агент; если их уже делает другой агент, команда и хук предупреждают. `review` и сводка «Что изменилось» вверху истории рассказывают изменения по концепциям; `health` и режим «Здоровье» в строке управления показывают красные, устаревшие, без проверки (есть файлы, нет команды и отметки «проверен»), план и риски — `TODO`, `FIXME`, `HACK`, `XXX` и строки, похожие на ключи, в файлах блоков; печатаются только файл и номер строки, `.env`, ключи и сертификаты не открываются.

**Плагин Claude Code — обязателен для агентов в Claude Code.** Инструкция `/agent` требует его первым шагом: `node mycel.mjs plugin --install` собирает плагин и подключает его (`claude` из PATH, иначе — тот, из чьей сессии запущена команда, по `CLAUDE_PID`; `--claude <путь>` — свой), повторно — безопасно, отдельно подключённый MCP-сервер `mycel` убирает; инструменты и хуки появляются в новой сессии. Без `--install` `node mycel.mjs plugin` только собирает в `.mycel/plugin` локальный маркетплейс с плагином `mycel`: MCP-сервер, хуки и навык с короткой инструкцией, пути — полные. Хуки: после `Write`, `Edit`, `MultiEdit`, `NotebookEdit` — `touch` файла и предупреждение, если блок делает другой агент; в конце ответа — просьба описать или подтвердить блоки, файлы которых агент менял в этой сессии (один раз подряд); в начале сессии — обзор карты (концепции и механика по строке, отметки, устаревшее, до 6000 символов) вместо чтения всего кода. Хук молчит, если Mycel не запущен, другой версии или папка не подключена. Подключает плагин человек: `claude plugin marketplace add <папка> --scope user` и `claude plugin install mycel@mycel-local --scope user` (отдельно подключённый MCP-сервер `mycel` тогда лучше убрать). Для Codex `plugin` печатает строки для `~/.codex/config.toml`.

**Виртуальная машина.** Mycel работает на основной машине; браузер и агенты в виртуальной машине (VMware, VirtualBox, Hyper-V, WSL) ходят к нему по сети виртуальных машин, и агент там настраивает всё сам. На основной машине `node mycel.mjs remote on` открывает доступ на адресах адаптеров виртуальных машин (или `--address`); `remote` показывает, что открыто, какие машины с доступом и команду установки; `remote revoke <id>` отзывает ключ машины; `remote off` закрывает доступ; настройка — в `.mycel/listen.json`. Агент в виртуальной машине выполняет `curl -fsS http://<адрес>:4317/install.sh | sh`: скрипт ставит Node.js 22+, если его нет (официальная сборка с nodejs.org с проверкой SHA-256 — в `~/.mycel-node`), копию Mycel в `~/mycel` (`/download/mycel.tar.gz`) и просит доступ (`join` без ключа). Он печатает четырёхзначный код; на любой странице Mycel на основной машине появляется карточка с тем же кодом и выбором проекта — человек сверяет код и нажимает «Разрешить». Машина получает свой ключ (в `.mycel/devices.json` — только хэш), сохраняет его вместе с адресом и проектом в своём `.mycel/remote.json`, и дальше команды, MCP и плагин работают из папки проекта там (файлы и проверки — локальные), `node mycel.mjs open` открывает браузер с ключом. Папку самой виртуальной машины агент подключает как обычно — `init` в её корне: проект создаётся на основной машине с пометкой этой машины (в реестре — `machine`, путь — в виртуальной машине, его основная не проверяет), на главной путь показан с «на машине «…»», а команды из этой папки там находят его сами; из папок без проекта берётся проект, выбранный при «Разрешить». Папки разных машин и основной не пересекаются; проверки и поиск рисков проекта машины запускаются только на ней. Создать проект может только машина со своим ключом (не ручной `join` с ключом основной). Машины с доступом видны на главной, «Отключить» отзывает ключ. На адресах виртуальных сетей без ключа открыты только `/api/health` (без `data`), `/agent`, `/install.sh`, `/download/mycel.tar.gz` и запрос доступа; ответить на запрос, подключить папку, остановить Mycel и открыть доступ можно только на основной машине; токен основной машины по сети не уходит (`remote --key` печатает его для ручного `join <адрес> <ключ>`). Запрос живёт 10 минут, от одного адреса — один, всего — до пяти. Брандмауэр Windows должен пропускать node, а VPN — не забирать сеть виртуальных машин. Адреса — только локальной сети.

**Любой агент и локальные модели.** Всё, что делает плагин Claude Code, доступно и без него:
- `node mycel.mjs watch` — слежение за папкой проекта: изменённые файлы отмечаются на карте сами (их блоки «устарел?», над ними имя — `editor` или `--actor`), кто бы их ни правил: любой агент или человек в редакторе. Зависимости, сборка, `.git`, данные и файлы с секретами не смотрятся.
- `node mycel.mjs hook --from codex|cursor` — хуки Codex (`~/.codex/hooks.json`: правка через `apply_patch`, `Stop`, `SessionStart`) и Cursor (`~/.cursor/hooks.json`: `afterFileEdit`, `stop`, `sessionStart`) с тем же смыслом, что у плагина; готовые записи печатает `plugin --agent codex|cursor`. Формы событий — по документации агентов, вживую в них не проверено.
- `node mycel.mjs tools [--format openai|mcp]` — описания всех инструментов для вызова функций; `node mycel.mjs call <инструмент> '<json>'` (или `-` — JSON со стандартного ввода) — вызов, как через MCP. Так Mycel подключается к своему агенту или фреймворку без MCP.
- `node mycel.mjs chat [--model имя] [--base адрес/v1] ['задача']` — встроенный агент для локальной модели на сервере с OpenAI-совместимым API и вызовом функций: Ollama (по умолчанию `http://127.0.0.1:11434/v1`), LM Studio (`http://localhost:1234/v1`), llama.cpp `llama-server`, vLLM; ключ — `MYCEL_LLM_KEY`, модель — `MYCEL_LLM_MODEL` или первая из `/models`. Модель получает короткую инструкцию (`mycel guide --short`), обзор карты, все инструменты Mycel (кроме долгого ожидания) и чтение файлов проекта (`list_files`, `read_file`, `search_files`; `.env`, ключи и двоичные файлы не читаются); код она не меняет. Имя на карте — `local-<модель>`. После ответа — одно напоминание описать блоки, файлы которых отмечены от её имени. С текстом задачи — один ход, без него — разговор.
- `plugin --agent` печатает записи и для клиентов локальных моделей: `lmstudio`, `continue`, `goose`, `opencode`, `jan`, `openwebui` (через прокси `mcpo`).

**Без чата.** Человек говорит с агентом в окне агента (Claude Code, Codex), и агент отвечает там же. Mycel сообщает агенту только то, что человек сделал на карте кнопками: закончил правки, принял или отклонил предложение, — через `wait`, `changes` и `context` («Человек в Mycel»). Что человек выделил и в каком блоке работает, агент видит в `context` и `selection`. Агент показывает человеку, что делает сейчас (`doing`), и блок, о котором говорит (`show`).

**MCP.** `mcp.mjs` — MCP-сервер для агентов (stdio, без зависимостей): инструменты `mycel_guide`, `mycel_projects`, `mycel_init`, `mycel_context`, `mycel_changes`, `mycel_wait`, `mycel_selection`, `mycel_apply`, `mycel_build`, `mycel_propose`, `mycel_mark`, `mycel_doing`, `mycel_show` — те же команды `mycel.mjs`, пакеты передаются объектом, без файлов. Агент подписывается по имени клиента (Claude Code — `claude`, Codex — `codex`) или `MYCEL_ACTOR`; проект — по папке, где запущен агент (`CLAUDE_PROJECT_DIR`), или параметрами `project` и `folder`. `mycel_wait` по умолчанию ждёт до 25 минут: Claude Code сам уводит долгий вызов в фон и сообщает, когда он закончился. В Claude Code MCP-сервер подключается только плагином (см. «Плагин Claude Code»), отдельно — не нужно: инструменты бы повторялись. Другие агенты подключают тот же MCP-сервер: `node mycel.mjs plugin --agent <имя>` печатает запись и файл настроек — `codex` (`~/.codex/config.toml` или `codex mcp add`), `cursor` (`~/.cursor/mcp.json`), `antigravity` (сменил Gemini CLI: `~/.gemini/config/mcp_config.json`), `gemini` (`~/.gemini/settings.json` или `gemini mcp add`), `vscode` (`.vscode/mcp.json`, ключ `servers`), `windsurf` (Devin Desktop: `~/.config/devin/mcp_config.json`), `cline`, `claude-desktop`; пути — по документации агентов на 28.10.2026. Хуков у этих записей нет: после правки файлов агент вызывает `mycel_touch` (`mycel touch`), перед концом работы обновляет блоки или `mycel_fresh`.

**Правки человека.** Первая запись человека, которая меняет содержимое карты (не сворачивание, уровень или перемещение), начинает правки: внизу посередине карты появляется «Закончить правки» с числом записей. Пока кнопку не нажали, его записи с начала правок приходят в `changes` (`held` — сколько их), но `wait` на них не просыпается, а `context` и `changes` пишут «Человек сейчас правит карту». Кнопка (`POST /api/p/<id>/edits`) пишет событие `kind: 'edits'` с `edits: { since, until, count }`; оно будит агента, и `wait` печатает все правки с начала. Начатые правки хранятся в `edit.json` проекта и переживают перезапуск. События хранятся в `.mycel/projects/<id>/chat.json` (там же прежняя переписка проектов, у которых был чат), последние 500, и не меняют ревизию карты.

**Уровни.** Строя карту, агент раскладывает её по четырём уровням вложенности. Концепция (блоки основной карты) и механика (их подкарты) — для человека без программирования: название в 1–4 простых слова, текст — одно короткое предложение, связи подписаны простыми словами, проблемы — заметками простыми словами. Техника (подкарты механики) — для разработчиков: компоненты, файлы и библиотеки в `обратных кавычках`, настройки, данные, технические риски заметками; она есть у каждого блока механики. Код (подкарты техники и глубже) — шаги в порядке выполнения: действие в названии, функция и файл в тексте; он строится там, где несколько осмысленных шагов. В `context` у каждого блока указан его уровень, у каждой связи — id (`· id: …`) для `update-edge` и `delete-edge`. На уровне кода авторасстановка ставит шаги сверху вниз, выше — слева направо.

**Проверка уровней.** `build` и `apply` до записи проверяют то, что пакет добавляет или меняет на концепции и механике: блоки и заметки (название не длиннее 40 символов, текст — 200) и подписи связей, оба конца которых на этих уровнях. Обратные кавычки, вызовы `name()` и `send(message)`, имена файлов кода и настроек и пути (`UI/Button.tsx`), имена вроде `BOT_TOKEN`, `handle_message`, `getResponse`, `message.text`, `JSON.parse`, классы вроде `CartService`, `BotHandler` — нарушение; названия продуктов (Telegram, OpenAI, PDF, Node.js), адреса сайтов (openai.com), имя бота и команды в Telegram (`@study_buddy_bot`, `/set_language`) — нет. Жаргон («диспетчер», «polling») проверка не ловит — за ним следит агент. При нарушении ничего не записывается: команда печатает каждое нарушение (блок, уровень, фрагмент) и куда перенести подробности — в подкарту, на уровень «Техника» — и завершается с кодом 1. `build` проверяет только то, что запишет, поэтому повтор прерванного `build` не спотыкается о записанное. `apply` считает уровни по карте, которую агент прочитал; если её уже изменили, сразу печатает изменения. `--no-check` пропускает проверку — только когда человек сам попросил такую формулировку. Старое содержимое и правки человека в интерфейсе не проверяются.

Адрес Mycel — `--url` или `MYCEL_URL`, по умолчанию `http://127.0.0.1:4317`; каталог данных — `--data` или `MYCEL_DATA`, по умолчанию `.mycel` рядом с `mycel.mjs`; проект — `--project ID`, по умолчанию проект текущей папки. Имя агента — `--actor` или `MYCEL_ACTOR`; без них в Claude Code — `claude`, иначе `agent`. Причина записи — `-m`. `--no-start` — не запускать Mycel, если он не работает; `--no-check` — `build` и `apply` без проверки уровней. Изменения выводятся текстом: записи истории с автором и временем, затем добавленные и изменённые блоки целиком в текущем виде, удалённое, связи.

**Уведомления.** `wait` держит долгий запрос к серверу и завершается, как только человек что-то сделает кнопками Mycel (закончит правки, решит по предложению) или кто-то, кроме этого агента, изменит содержимое карты: добавит или удалит блок, заметку или связь, поменяет текст, название, цвет, подпись, перенесёт узел в другую подкарту или прикрепит заметку. Перемещения, размеры и сворачивание его не будят — они копятся и приходят вместе со следующей правкой содержимого; `wait --all` будит на любую правку. Правки человека будят только целиком — когда он нажмёт «Закончить правки». Собственные записи агента его не будят. В Claude Code команда запускается в фоне, и её завершение приходит агенту уведомлением с изменениями; после него агент запускает `wait` снова. Агент без фоновых задач вызывает `changes` в начале каждого шага.

**Структура целиком.** `build` принимает дерево: блоки с вложенными `blocks` (подкарты) и `notes` (заметки к блоку), свободные `notes` и `links`. `id` можно не указывать — он составится из названия латиницей; связь ссылается на `id` или однозначное название. `parent` строит структуру внутри существующего блока. `build` пишет структуру по шагам с короткими паузами — сначала уровень самой структуры, затем подкарты, — чтобы человек видел, как карта растёт; `--at-once` пишет одной записью, итог одинаковый. Уже записанные блоки (тот же id или название на том же уровне), заметки и связи пропускаются, поэтому прерванный `build` можно просто повторить. Если человек правит карту между шагами, `build` продолжает поверх его правок, пока они не задевают строящееся, и сразу печатает их; в «Записано, ревизии …» — только свои ревизии.

```json
{
  "message": "Карта проекта по коду",
  "blocks": [
    { "id": "server", "title": "Сервер", "text": "Хранит карты и отдаёт их", "color": "green",
      "blocks": [ { "id": "api", "title": "Запросы", "text": "Принимает правки карты",
                    "blocks": [ { "title": "HTTP API", "text": "`server.mjs`, маршруты `/api/p/<id>`" } ] },
                  { "id": "store", "title": "Хранилище", "text": "Сохраняет карту на диск",
                    "blocks": [ { "title": "Запись на диск", "text": "`src/store.mjs` пишет `graph.json` атомарно" } ] } ],
      "notes": ["Проверить лимиты"] },
    { "id": "ui", "title": "Интерфейс", "color": "blue" }
  ],
  "links": [ ["ui", "server", "правки"], { "from": "api", "to": "store" } ]
}
```

Сервер раскладывает новые блоки сам: на основной карте — правее существующего, в подкарте — под её содержимым; источник связи левее цели (связь с блоком внутри подкарты считается связью с самой подкартой), порядок в колонке подбирается так, чтобы связи меньше пересекались, заметки справа от своего блока, подкарта растёт под вложенное и раздвигает соседей: те, что ниже, сдвигаются вниз, правее — вправо ровно настолько, чтобы не было наложений; размер блока подбирается под текст. Связывайте части одного уровня: стрелка от «Интерфейса» к «Серверу», а не к блоку внутри него, — так схема читается, что за чем идёт. Уже нарисованную карту упорядочивает операция `layout`.

## HTTP API

Базовый URL: `http://127.0.0.1:4317`. Ответы JSON, кроме инструкции и контекста (текст) и потоков событий SSE.

Приложение и проекты:

| Метод | Путь | Результат |
|---|---|---|
| GET | `/agent` | Инструкция для агента с командой Mycel этого компьютера (текст) |
| GET | `/api/health` | `{ ok, app: "mycel", version, data }`; из виртуальной машины без ключа — без `data` |
| GET, POST | `/api/remote` | Только на основной машине: `{ port, listening: [{ address, listening, error? }], interfaces: [{ name, address, vm }] }`; POST `{ addresses }` — на каких адресах своих адаптеров принимать запросы виртуальных машин (пустой список — закрыть) |
| GET | `/api/session` | Токен, каталог данных, порт, платформа — для интерфейса и `mycel.mjs` |
| GET | `/api/projects` | Все проекты: `id`, `name`, `path`, `exists`, `createdAt`, `updatedAt`, `revision`, `blocks`, `notes`, `edges`, `agents`, при ошибке открытия — `error` |
| GET | `/api/projects?path=<папка>[&root=<корень>]` | Проект, в папке которого лежит `path` (ближайший); с `root` — только внутри него. 404, если папка не подключена; у удалённого проекта в ответе `deleted` |
| POST | `/api/projects` | `{ path, root?, name?, id?, move?, new? }` — подключить папку: та же папка — тот же проект (`created: false`), подпапка подключённого — его проект (`ancestor: true`), иначе новый (`created: true`). С `root` (корень git-репозитория) папки выше него — живые и удалённые — репозиторий не захватывают. `id` переносит проект в новую папку (`moved: true`), если прежней нет или задан `move`. Папка удалённого проекта — 409, если не задан `new` |
| POST | `/api/projects/<id>/delete` | Удалить проект в корзину. Пока папка переносится (до ~2 с), маршруты проекта отвечают 503 `{ retry: true }`; `{ deleted: true }` получают только после переноса. Папка занята — 409, проект продолжает работать |
| POST | `/api/projects/<id>/restore` | Вернуть из корзины |
| GET | `/api/events` | SSE главной страницы: `{ projects }` при изменении списка, `{ project, revision }`, `{ project, chat }`, `{ project, presence }` |
| POST | `/api/stop` | Остановить Mycel, запущенный из командной строки |

Для POST нужны `Content-Type: application/json` и `Authorization: Bearer <token>`. Заголовок `X-Mycel-Actor: <имя>` отмечает агента на связи с проектом; `mycel.mjs` ставит его сам. Токен лежит в `.mycel/token`, сохраняется между запусками и не должен попадать в Git.

Сервер слушает только `127.0.0.1` и проверяет Host, Origin и Fetch Metadata (`/agent` — только Host: инструкцию открывают откуда угодно, токена в ней нет). Это инструмент для доверенной локальной машины, без изоляции пользователей операционной системы.

### Модель

Узел: `id`, `type` (`block` или `note`), `parentId` (уровень: `null` для основной карты или id блока-контейнера), `attachedTo` (только у заметки: id блока того же уровня, к которому она прикреплена, или `null`), `collapsed` (у блока с подкартой: свёрнута ли она), `title` (до 200 символов, у заметок не показывается), `text` (до 20000), `x`, `y` (координаты левого верхнего угла), `w`, `h` (120–20000 × 60–20000 — с запасом под большую подкарту; по умолчанию 220 × 110 у блока и 160 × 120 у заметки), `color` (`""`, `gray`, `red`, `orange`, `yellow`, `green`, `blue`, `purple`; у заметки по умолчанию `yellow`), `status` (только у блока, необязательно: `plan` — логика без готового кода, пунктир; `testing` — проверка идёт сейчас, рамка пульсирует; `passed` — код написан и проверен, зелёная рамка; `failed` — проверка не прошла, красная), `proposed` (только в открытом предложении агента: `add`, `change`, `remove`; ставит сервер).
Связь: `id`, `source`, `target`, `label` (до 200), `proposed` (как у узла). Связи соединяют только блоки; между двумя блоками в одном направлении может быть только одна связь.
Карта с открытым предложением агента: `proposal` — `{ title, by, at, nodes, edges }`, где `nodes` и `edges` — прежнее содержимое изменённого им.

Координаты узла основной карты — мировые. У вложенного узла `x` и `y` отсчитываются от левого верхнего угла поля подкарты: поле лежит внутри рамки контейнера (1 px) с отступом 12 px слева и под шапкой высотой 36 px, или 75 px, если у контейнера есть текст. `w` и `h` контейнера — размер развёрнутой подкарты; если содержимое не помещается, на экране она шире или выше. Свёрнутая подкарта — карточка шириной не больше 280 px. Пока указатель над полем, интерфейс не даёт увести вложенный узел левее и выше поля, но API отрицательные координаты принимает.

При перемещении блока через `update-node` сервер сдвигает его прикреплённые заметки на то же расстояние; вложенные узлы переезжают сами, потому что их координаты относительны. Удаление блока удаляет всё вложенное, прикреплённые заметки и связи. Блок не может лежать внутри самого себя.

### Изменить карту

Сначала прочитайте `/api/p/<id>/graph` и возьмите `revision`, затем отправьте пакет в `POST /api/p/<id>/changes`:

```json
{
  "expectedRevision": 0,
  "actor": "coding-agent",
  "message": "Добавлен сценарий доставки",
  "operations": [
    { "type": "add-node", "node": { "id": "delivery", "title": "Доставка", "text": "Адрес → способ → срок", "x": 700, "y": 0 } },
    { "type": "add-node", "node": { "id": "courier", "title": "Курьер", "x": 1040, "y": 0 } },
    { "type": "add-edge", "edge": { "source": "delivery", "target": "courier", "label": "адрес" } },
    { "type": "add-node", "node": { "type": "note", "attachedTo": "courier", "text": "Уточнить зоны доставки", "x": 1220, "y": -90 } },
    { "type": "add-node", "node": { "id": "courier-slot", "parentId": "courier", "title": "Интервал", "x": 0, "y": 0 } }
  ]
}
```

Успешный запрос возвращает новый граф и увеличивает ревизию на один. Ошибка любой операции отклоняет весь пакет. `id` узлов должны быть свободны. Проверку уровней делает `mycel.mjs`, а не сервер: запрос к API напрямую и правки в интерфейсе не проверяются.

Операции:

- `add-node` с `node`; без `id` сервер создаёт UUID, без `type` — блок. Вложенный узел: `parentId` существующего блока. Заметка: `"type": "note"`, при желании `attachedTo` блока того же уровня. Без `x` и `y` узел расставляется автоматически после всего пакета, а без `w` и `h` размер подбирается под текст.
- `update-node` с `id` и `patch`: `title`, `text`, `x`, `y`, `w`, `h`, `color`, `parentId`, `attachedTo`, `collapsed`, `status` (`null` снимает отметку). Прикреплённые заметки следуют за блоком с тем же смещением, в том числе при смене `parentId`.
- `delete-node` с `id`: удаляет узел, его заметки и связи.
- `add-edge` с `edge`: `source`, `target`, необязательные `id`, `label`.
- `update-edge` с `id` и `patch`: `label`, `source`, `target`.
- `delete-edge` с `id` связи.
- `layout` — заново расставить уровень: без `parentId` основную карту, с `parentId` подкарту блока, а сам блок подгоняется под её содержимое; с `"deep": true` — и всё внутри подкарт, которые при этом сжимаются под содержимое. Ручная расстановка этих узлов заменяется.

Ограничения: 2000 узлов (блоков и заметок), 8000 связей, 1000 операций на пакет, 1 МБ на запрос. `actor` — имя, указанное клиентом, а не подтверждённая личность.

При **409 Conflict** перечитайте карту и объедините изменения. Не заменяйте старым полным блоком актуальные данные, просто подставив новую ревизию.

Пример клиента без `mycel.mjs` добавляет блок в карту проекта; хаб ставит его правее остальных:

```sh
node examples/agent-update.mjs http://127.0.0.1:4317 .mycel/token my-product "Доставка" "Курьер или самовывоз" "Добавлен блок доставки"
```

## Хранение и обновление

`.mycel/` рядом с программой:

```
projects.json, projects.backup.json   реестр проектов: id, название, папка, дата
projects/<id>/                        карта (graph.json, graph.backup.json), события для агентов (chat.json), начатые правки (edit.json), устаревшие блоки и риски (code.json), отметки агентов (agents/), project.json
trash/<id>/                           удалённые проекты, 7 дней
token, server.lock, server.log        токен API, блокировка единственного процесса, вывод Mycel в фоне
listen.json, devices.json              адреса для виртуальных машин (mycel remote) и машины с доступом (хэши ключей)
remote.json                           в копии Mycel в виртуальной машине: адрес, ключ и проект основной (mycel join)
plugin/                               плагин Claude Code этого компьютера (mycel plugin)
```

Реестр пишется через временный файл с копией предыдущего; если он повреждён, Mycel берёт копию, а без неё собирает реестр заново из `projects/*/project.json`. Проект, карту которого не удалось открыть, остаётся в списке с ошибкой и не перезаписывается.

`graph.json` содержит карту и историю. Запись проходит последовательно: временный файл → сброс на диск → копия предыдущей версии в `graph.backup.json` → атомарное переименование.

Карты прежних версий (вложенные блоки с полями суть, логика, критерии, вопросы) при первом открытии переводятся в свободный формат: вложенность становится связями родитель → ребёнок, поля собираются в текст блока, блоки расставляются деревом слева направо. Исходный файл сохраняется как `graph.v1.backup.json` или `graph.v2.backup.json`. Повторный запуск не повторяет миграцию.

Повреждённый JSON не перезаписывается. Для восстановления остановите сервер, сохраните повреждённый файл отдельно и восстановите `graph.json` из резервной копии или ранее экспортированного JSON.

`server.lock` не допускает два Mycel с одним каталогом данных. Lock, оставленный аварийно завершённым процессом, снимается при следующем запуске сам.
