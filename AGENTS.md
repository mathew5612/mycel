# Mycel

Read [CONCEPT.md](CONCEPT.md) and [PROJECT_STATE.md](PROJECT_STATE.md) first. They are the memory of the user's requirements and of the project's current state. Where they disagree with earlier decisions, the latest requirements in CONCEPT.md win: today this is one app with a list of projects whose maps agents connect, build while the person watches, read and track (requirements 7–34), not the earlier one-nesting-level-per-screen view and not a server per project. There are four levels: Concept and Mechanics for people who do not program, Technical and Code for developers; double-clicking a block with a sub-map dives into it, and the level is chosen with a slider. Mycel has no chat: people talk to the agent in the agent's own window; the person's edits reach the agent as one batch, when they press "Finish edits". A block without finished code is dashed, a passed one is green, a failed one is red; the agent proposes logic changes that are not yet approved (`propose`), and the person accepts them.

A small local tool with no external dependencies. Keep the one-click launch (`Mycel.cmd` → `node mycel.mjs open`) and `node server.mjs` working without a build step or package installs, unless the task clearly needs something else.

- Before making changes, read docs/reference.md (the full description) and the modules involved.
- If Mycel is running, work with this repository's map as an agent: the guide is at `http://127.0.0.1:4317/agent` (or `node mycel.mjs guide`); after changes in meaning, update the matching blocks. The operations contract is in docs/reference.md.
- The app's data is in `.mycel/` next to the program; Mycel does not write into project folders. Do not write into `.mycel/` while Mycel is running; do not put tokens or working data into Git.
- Sub-map geometry is defined in `public/app.js` and repeated in `src/layout.mjs`: change them together. The step-by-step `build` in `mycel.mjs` computes the final layout locally through `src/model.mjs`, so the layout must stay deterministic.
- Agent proposals and block marks are pure functions in `src/model.mjs` (`propose`, `acceptProposal`, `rejectProposal`, the `status` field); only the server sets `proposed` flags, an edit cannot set them. Mark names are repeated in `mycel.mjs` and `server.mjs` (`context`).
- Levels (names by depth) and the check of an agent's batch before it is written are in `src/levels.mjs`; level names are repeated in `public/app.js`, level rules in `src/agent-guide.md` and in the `context` text in `server.mjs`: change them together.
- `src/agent-guide.md` is the agent guide, served by `GET /agent` and `mycel.mjs guide` through `src/guide.mjs`; keep the `{{url}}`, `{{command}}`, `{{readme}}` placeholders.
- Access from a virtual machine (`server.mjs`: `handle(req, res, remote)`, `listen.json`; `mycel.mjs`: `remote`, `join`, `remote.json`): on virtual network addresses only with a key; the token is never handed out over the network; `/api/stop`, connecting folders and `/api/remote` only from the main computer. Do not open Mycel on all addresses (`0.0.0.0`) or on addresses outside the local network. Access requests and machine keys are in `src/access.mjs` (`devices.json`, hashes only); only the person approves a request, with a button on the main computer: do not give agents a command that answers a request by itself. A virtual machine's project is the `machine` field in the registry (`src/hub.mjs`: `owner`, `nearest`, `lookup`, `connect` compare folders only within one machine); the main computer does not check its folder.
- Agent tools are one list in `src/tools.mjs`: the MCP server (`mcp.mjs`), `mycel tools`/`call` and the built-in agent `mycel chat` (`src/agent.mjs`) all take it from there; add new agent commands there. Hooks from different agents are brought to one shape by `hookEvent` in `mycel.mjs`. The built-in agent does not change project code and does not read secrets.
- Check changes to the model, API, storage and CLI with `node --test test/*.test.mjs` (Node 24 does not accept the `test/` folder without a glob). Tests must not touch the real `.mycel/` or port 4317.
- Check the interface in a browser. For purely visual changes a visual check is enough; do not add tests that check nothing.
- Keep optimistic concurrency: every mutation requires expectedRevision. Do not get around a 409 by blindly overwriting. The only exceptions are marks: the person's decision on a proposal and the marks from `check` (`markNow` in `mycel.mjs`) are written on top of the current revision.
- Code and map: a block's files and check command (`files`, `test`) are in `src/model.mjs`; "being edited", "outdated?" and risks are in the hub (`touchFiles`, `freshen`, `code.json`); Claude Code hooks are `mycel.mjs hook`, the plugin is built by `mycel.mjs plugin`. A hook must never get in the agent's way: on any error, exit quietly with code 0. The hub does not run check commands; the agent runs them (`check`). `health` does not print the content of the lines it finds and does not open `.env`, keys or certificates.
- Interface texts are short and to the point: no slogans, eyebrow headings, hints in empty areas or panels that retell the map. One muted palette, one accent colour, fonts no smaller than 12px.
- Agents work through `mycel.mjs`, the MCP server `mcp.mjs` (the same commands as `mycel_*` tools; add new commands to both) and the HTTP API; in Claude Code only through the plugin (`mycel plugin --install`), do not suggest connecting the MCP server separately; do not add pages or hints about agents to the interface unless the user asks (the line with the guide address on the home page was added at their request).
