# Mycel

Сначала прочитай [CONCEPT.md](CONCEPT.md) и [PROJECT_STATE.md](PROJECT_STATE.md). Это память о требованиях пользователя и текущем состоянии проекта. При расхождениях с прежними решениями приоритет имеют последние требования в CONCEPT.md: сейчас это одно приложение со списком проектов, карты которых агенты подключают, строят на глазах у человека, читают и отслеживают (требования 7–32), а не прежний показ одного уровня вложенности на экране и не сервер на каждый проект. Уровней четыре: концепция и механика — для людей без программирования, техника и код — для разработчиков; двойной клик по блоку с подкартой погружает в него, уровень выбирается ползунком. Чата в Mycel нет: с агентом говорят в его окне; правки человека доходят до агента пачкой — по кнопке «Закончить правки». Блок без готового кода — пунктир, проверенный — зелёный, с ошибкой — красный; неутверждённые изменения логики агент предлагает (`propose`), принимает их человек.

Небольшой локальный инструмент без внешних зависимостей. Сохраняй запуск одним кликом (`Mycel.cmd` → `node mycel.mjs open`) и `node server.mjs` без сборки и установки пакетов, если задача явно не требует другого.

- Перед изменениями прочитай docs/reference.md (полное описание) и затронутые модули.
- Если Mycel запущен, работай с картой этого репозитория как агент: инструкция — `http://127.0.0.1:4317/agent` (или `node mycel.mjs guide`); после смысловых изменений обнови соответствующие блоки. Контракт операций в docs/reference.md.
- Данные приложения — `.mycel/` рядом с программой; в папки проектов Mycel не пишет. Не пиши в `.mycel/` при работающем Mycel; не включай токены и рабочие данные в Git.
- Геометрия подкарты задана в `public/app.js` и повторена в `src/layout.mjs`: меняй их вместе. Пошаговый `build` в `mycel.mjs` считает итоговую раскладку локально через `src/model.mjs`, поэтому раскладка должна оставаться детерминированной.
- Предложение агента и отметки блоков — чистые функции в `src/model.mjs` (`propose`, `acceptProposal`, `rejectProposal`, поле `status`); пометки `proposed` ставит только сервер, правкой их не поставить. Названия отметок повторены в `mycel.mjs` и `server.mjs` (`context`).
- Уровни (названия по глубине) и проверка пакета агента перед записью — `src/levels.mjs`; названия уровней повторены в `public/app.js`, правила уровней — в `src/agent-guide.md` и в тексте `context` в `server.mjs`: меняй их вместе.
- `src/agent-guide.md` — инструкция агенту, её отдают `GET /agent` и `mycel.mjs guide` через `src/guide.mjs`; держи подстановки `{{url}}`, `{{command}}`, `{{readme}}`.
- Доступ из виртуальной машины (`server.mjs`: `handle(req, res, remote)`, `listen.json`; `mycel.mjs`: `remote`, `join`, `remote.json`): на адресах виртуальных сетей — только с ключом, токен по сети не раздаётся, `/api/stop`, подключение папок и `/api/remote` — только с основной машины. Не открывай Mycel на всех адресах (`0.0.0.0`) и на адресах вне локальной сети. Запрос доступа и ключи машин — `src/access.mjs` (`devices.json`, только хэши); разрешает запрос только человек кнопкой на основной машине — не добавляй агентам команду, которая отвечает на запрос сама. Проект виртуальной машины — поле `machine` в реестре (`src/hub.mjs`: `owner`, `nearest`, `lookup`, `connect` сравнивают папки только в пределах одной машины); его папку основная машина не проверяет.
- Инструменты для агентов — один список `src/tools.mjs`: его берут MCP-сервер (`mcp.mjs`), `mycel tools`/`call` и встроенный агент `mycel chat` (`src/agent.mjs`); новую команду для агентов добавляй туда. Хуки разных агентов приводит к одному виду `hookEvent` в `mycel.mjs`. Встроенный агент не меняет код проекта и не читает секреты.
- Проверяй изменения модели, API, хранения и CLI командой `node --test test/*.test.mjs` (каталог `test/` без маски Node 24 не принимает). Тесты не должны трогать настоящий `.mycel/` и порт 4317.
- Проверяй интерфейс в браузере. Для чисто визуальных правок достаточно визуальной проверки; не добавляй бессодержательные тесты.
- Сохраняй оптимистическую конкуренцию: каждая мутация требует expectedRevision. Не обходи 409 слепой перезаписью. Исключения — только отметки: решение человека по предложению и отметки `check` (`markNow` в `mycel.mjs`) пишутся поверх текущей ревизии.
- Код и карта: файлы и команда проверки блока (`files`, `test`) — в `src/model.mjs`; «правится сейчас», «устарел?» и риски — в хабе (`touchFiles`, `freshen`, `code.json`); хуки Claude Code — `mycel.mjs hook`, плагин собирает `mycel.mjs plugin`. Хук не должен мешать агенту: при любой ошибке — тихий выход с кодом 0. Хаб не запускает команды проверки — их запускает агент (`check`). `health` не печатает содержимое найденных строк и не открывает `.env`, ключи и сертификаты.
- Тексты интерфейса короткие и по делу: без лозунгов, eyebrow-заголовков, подсказок на пустых местах и панелей, пересказывающих карту. Одна приглушённая палитра, один акцентный цвет, шрифты не мельче 12px.
- Агенты работают через `mycel.mjs`, MCP-сервер `mcp.mjs` (те же команды инструментами `mycel_*`; новую команду добавляй в оба) и HTTP API; в Claude Code — только через плагин (`mycel plugin --install`), отдельное подключение MCP-сервера не предлагай; не добавляй в интерфейс страницы и подсказки про агентов без запроса пользователя (строка с адресом инструкции на главной — по его запросу).
